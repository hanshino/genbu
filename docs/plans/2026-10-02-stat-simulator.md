# 屬性模擬器（角色面板 / 配裝）

> 狀態：**規劃中**。公式與資料來源見 `docs/stat-simulator-formulas.md`。
> 建立於 2026-10-02。

---

## 這份文件要解決什麼

讓玩家在網站上建立「自己遊戲裡的角色」：選門派、等級、轉生、配點、裝備、被動，算出跟遊戲一致的角色面板，並能存多隻角色。

長期目標是幫玩家判斷**值不值得**：換一件已強化 +N 的裝備、繼續強化、多加屬性點、升被動，各要花多少成本、面板（之後是傷害）能多多少，CP 值哪個最高。第一版只做面板，但資料結構要讓之後的比較功能不用重寫。

---

## 架構：三層

### 1. 角色檔（純資料）

可序列化成 JSON，帶 `version` 欄位，之後改格式可以遷移。

- 名稱、門派、等級、**轉生點數總和**（每次轉生的等級選填，填了就換算成總和）、六圍配點（**一律存不含裝的值**）
- 各裝備欄：`itemId` + 強化 `+N` + 手動加值（鑲嵌 / 隨機屬性）
- 被動技能等級、收藏等級、經脈規劃字串（沿用經脈模擬器的 `encodePlan`）
- 英雄 / 陣法手動加值

裝備**只存 `itemId`，數值計算時才從 DB 讀**：遊戲改版調數值，角色會跟著更新。

第一版存在 localStorage `genbu.characters`（多角色）。之後登入的玩家要跨裝置同步，就是把同一份 JSON 存到 user DB（`src/lib/user-db.ts`）。

### 2. 計算引擎

`computePanel(角色, 遊戲資料) → 面板`，純函式。

- 每一項數值附上**來源明細**（屬性 / 裝備 / 強化 / 被動 / 經脈 / 手動），加上「估計」旗標（`docs/stat-simulator-formulas.md` §8 列的未解項目）。
- 遊戲資料（道具數值、強化表、`magic_stats`）由伺服器先查好傳進來，引擎本身不碰 DB，所以 client 端也能跑。
- 驗收：formulas §7 的麒麟 Lv198 與 §9 的三隻角色寫成 fixture 測試，面板逐項吻合。

### 推算轉生點數（第一版要做）

很多玩家不知道自己在幾等轉生。面板公式只用到等級，轉生只影響點數總和，所以只要推出總和就夠：

```
轉生點數總和 = 六圍加點成本（不含裝）+ 剩餘點數 − 升級點數(Lv)
```

- 遊戲角色視窗顯示的是**含裝六圍**和**剩餘點數**，所以主要入口是「填含裝六圍」：系統扣掉裝備給的六圍（道具本身 + 強化 + 鑲嵌 + 隨機屬性）換成不含裝的值。**裝備要先填完、填對**，推算才準。
- 配點分頁有「含裝 / 不含裝」切換，用哪種填都存成不含裝的值；之後換裝備時，不含裝的值保持不變，跟遊戲一樣。
- 轉生欄有兩個模式：「我知道每次轉生等級」/「幫我推算」。推算模式顯示前置清單（等級、剩餘點數、六圍、已填裝備數），齊了才出結果。
- **檢查**：合法總和是 0 或 10–140（單次 10–35、最多 4 轉，中間每個整數都可能）。算出 1–9、負數或超過 140 時，提示檢查裝備 / 強化等級。只能推出總和，沒辦法拆成每次的等級。
- 有任何一項不含裝屬性 ≥146 時，成本是推測的，結果標「估計」。
- 轉生只能在 Lv100–140 之間（滿等 140 就得轉），四轉都轉完才能練到 140 以上。所以**角色等級 > 140 時一定是四轉**，總和必須在 40–140；不在這個範圍就是資料填錯。選填的轉生等級也只能選 100–140。

### 被動技能選單（第一版要做）

選主門派後自動帶出技能，**只列會影響面板的被動**（formulas §6a 有 `magic_stats` 的 + §6b 的 22 個），附技能圖示（`magic_images`）。

分組（依 `magic.clan`，2026-10-02 查 DB）：

| 組 | 來源 | 例 |
|---|---|---|
| 主門派 | 主門派對應的 clan；曼陀 / 麒麟共用 `CLASS_MONTO_KYLIN`，火狐 / 雪狼共用 `CLASS_FOX_SNOW` | 劍刃修練、劍心修煉 |
| 副門派 | 神武 `CLASS_GOD`、少林 `CLASS_SHAULIN`、無名島 `CLASS_ISLE`、天師 `CLASS_MAGIC`；任何主門派都能選，**最多同時兩個** | 鍛體修煉、煉心修煉、棍法修行、暗器修練、拔刀術 |
| 通用 | `clan` 為空 | 劍格擋、強筋健骨、嫁衣神功 |
| 家族 | `CLASS_GUILD` | 氣通八脈、鍛筋鍊髓 |

- 收藏（1151～1159）和經脈有各自的輸入，不列在這裡，避免重複計算。
- **「全滿」按鈕**：每組一顆，加上一顆全部。滿級取「`magic_learn.char_level` ≤ 角色等級」的最高級，不是無條件取技能最高級。
- 有武器條件的被動（§6b）在目前武器不符時變灰並標「需裝備 X」，等級照樣保留，換上符合的武器就生效。
- 角色檔的 `subSects` 存副門派（最多兩個）。

### 3. 比較與 CP 值（未來，第一版不做）

- **換裝效益**：複製角色、換掉裝備，兩份面板相減。
- **成本**：市價來自 `price_reports`，強化成本來自 `strong_formula` 的材料。CP 值 = 面板差 ÷ 成本。
- **精進建議**：把「外功 +1 點」「被動升 1 級」「某件強化 +1」都當成候選，各算一次差值，依 CP 值排序。
- **傷害**：`damage(面板, 怪物)` 疊在面板上面（公式研究中，見 formulas 附錄），效益就從「物攻 +80」變成「打某隻怪每下多 X」。
- **英雄加成**：可以從英雄組隊工具（`src/lib/hero-team-optimizer.ts`）帶入，不用手打。

## 已決定

- **規則放 genbu `src/configs/`**：門派係數、攻速表、§6b 的 help 被動都是實測擬合出來的係數，不是遊戲素材，不另外請 tthol_data 產表。
- **§6b 被動手寫對照表**（約 18 列：id → 各級數值、生效武器），不寫 help 解析器。
- **第一版範圍**：
  - 門派、等級、轉生點數（可推算）、六圍配點（含裝 / 不含裝切換）→ 剩餘點數 + 基礎面板
  - 裝備欄（沿用 `src/components/compare/item-picker.tsx`）+ 強化 `+N`
  - 被動技能選單（依主 / 副門派帶出、附圖示、全滿按鈕）、收藏等級選單
  - 鑲嵌、隨機屬性、英雄 / 陣法：手動加值欄位
  - 多角色存 localStorage
- **不在第一版**：傷害、遠程物攻、比較 / CP 值、伺服器同步、轉職前門派。

## 還沒決定 / 待確認

- 英雄 / 陣法加成會不會加到六圍（會的話會被屬性公式放大）。目前照「直接加在最終值」做。
- 經脈加成第一版要不要接（貼經脈模擬器的分享連結帶入）。
- 攻速表（`attack_speed.ini`）、收藏等級 → 技能等級對應、各裝備欄允許的道具類型：genbu 目前沒有，資料來源待確認。沒有的話先「表值 185 照公式、其他標估計」，收藏讓玩家逐項填技能等級。
- §7 的負重（差 155）與雙劍攻速本來就算不準，測試只驗「估計值 + 估計旗標」，不硬補數字。
