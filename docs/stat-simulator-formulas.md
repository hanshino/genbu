# 配裝 / 屬性點模擬器：公式與資料來源

給 genbu 實作「選門派 + 等級 + 屬性點 + 裝備 + 技能 → 算出角色面板」用。

這些公式是 2026-10 在遊戲內實測擬合出來的（tthol_data `scripts/stat_formula_investigation.md`，含每個點的原始數據）。方法是 Cheat Engine + tthol-memory 讀記憶體，再對照穿脫裝備、吃丹藥的前後變化。**公式不在客戶端**：伺服器算好送下來，客戶端照抄（`tthola.dat` 0x49E1F3 的封包 switch），所以只能實測。

符號：`Lv` 等級；外功 S、內力 P、根骨 V、身法 A、技巧 D、玄學 W 都是**含裝備加成的最終屬性**。

## 1. 計算順序

```
最終屬性 = 自己分配的點數 + 裝備的六圍加成
衍生值   = 屬性公式(最終屬性) + 裝備加成 + 被動技能加成 + 英雄 / 陣法 / 藥水（直接加，不會被放大）
```

裝備加成 = 道具本身數值 + 鑲嵌（真元 / 魂石） + 隨機屬性 + 強化 `+N`（見 §5）。

## 2. 共用公式（全門派，實測誤差 0）

分階函數：`Σ(x) = Σ_{k≥0} max(0, x − 5 − 10k)`。意思是從第 6 點起每 10 點升一階，**超過 200 也不封頂**。

```ts
const tier = (x: number) => { let s = 0; for (let t = x - 5; t > 0; t -= 10) s += t; return s; };
```

| 數值 | 公式 |
|---|---|
| 物攻（近戰） | ⌊3·S + 0.4·Σ(S)⌋ + 裝備 + 被動 |
| 內勁 | ⌊3·P + 0.3·Σ(P)⌋ + 裝備 + 被動 |
| 防禦 | 3·V + 裝備 + 被動 |
| 命中 | 3·D + Lv + 50 + 裝備 + 被動 |
| 閃躲 | 3·A + Lv + 50 + 裝備 + 被動 |
| 重擊 | 1 + ⌊D/25⌋ + ⌊0.15·W⌋ + 裝備 + 被動 |
| 拆招 | ⌊W/10⌋ + 1 + 裝備 |
| 負重上限 | 250·Lv + 100·S + 10000 + **身上裝備重量總和** + 被動（`Encumbrance`） |
| 移動速度 | 5 + 坐騎 / 飾品的 `run_speed` |
| 攻速 | 見 §4 |

- 浮點數取整前請加 `1e-9`，避免 `0.15·W` 這類算式被浮點誤差少算 1。
- 負重上限實測會多 0～215（空裝 0，穿裝多半 +2～+10，少數 +56 / +157），原因未明。猜測是某些裝備的實際重量跟 ITEM.BIN 不同。**可以標成近似值。**

### 遠程物攻（弓 BOW / 暗器 HIDDEN_WEAPON）

改用技巧計算。目前只有一個實測點（雪狼 Lv200，技巧 300、外功 16），兩種解釋都說得通：

- ⌊2.5·D + 0.3·Σ(D)⌋，外功不算（**較可能**）
- ⌊2.33·D + 0.3·Σ(D)⌋ + 外功的近戰公式

巴哈 2005 年的實測（[sn=1143](https://forum.gamer.com.tw/G2.php?bsn=6960&sn=1143)）是「1 技 → 物攻 2、10 技 → 26，每 10 點加 0.2」，只看技巧，跟第一種一致（2.5·10 + 0.2·5 = 26）。分階係數當年是 0.2，現在的單點要 0.3 才吻合，可能改過版。**仍標成估計值**。

最終值還要加上裝備和被動：

```
體力上限 = 200 + 10·Lv + a·Lv·(Lv+1) + k·V·(V+1)/2 + 裝備 hp + 被動
真氣上限 = 上表 + 裝備 mp + 被動
護勁     = 上表 + 裝備 magic_def + 被動
```

- **兩段分開無條件捨去再相加**：⌊200 + 10·Lv + a·Lv·(Lv+1)⌋ + ⌊k·V·(V+1)/2⌋。這是巴哈 2007 年的寫法（[sn=3142](https://forum.gamer.com.tw/G2.php?bsn=6960&sn=3142)，係數寫成 A·Lv² + (10+A)·Lv + 200 與 C·V·(V+1)，C = k/2；天外天 / 移花宮 / 惡人谷三派的 a、k 都跟我們一樣）。麒麟 Lv198 用這個取整法剛好 24110，沒有誤差。
- 名詞對照：`sect.ini` 的門派 ID 是 bitflag；`magic.clan` 用 `CLASS_*`（`src/lib/constants/magic-clan.ts`）。
- 無名島 16 / 少林 32 / 天師 64 / 神武（`CLASS_GOD`）是副門派，最多同時兩個，本身不影響公式，但會開放對應的被動技能（例如神武的鍛體修煉、煉心修煉）。
- **轉職前**的入門弟子 1 / 火狐弟子 256 / 曼陀弟子 1024 沒有實測，第一版可以不支援。
- 麒麟只測過 Lv198 一個等級，a = 0.45 是用單點推的；其他門派都至少有兩個等級交叉驗證。
- 同門派男女沒有對照組（惡人谷只測過女、天外天只測過男），目前假設性別不影響。

## 4. 攻速

- **空手 = 7 + ⌊A/25⌋**，實測身法 1～186 全部吻合。
- 拿武器時，`attack_speed.ini`（data1.pak）有「武器種類 × 門派」的表值，越小越慢：空手 185、匕首 180（天外天 185）、劍 175（移花宮 180）、法杖 165（火狐 / 曼陀系 175）、拳刃 150 …
  - 表值 185 的武器：= 7 + ⌊A/25⌋ + 武器的 `attack_speed`。巴哈玩家數據（雙刀 / 神兵：身法 117 → 12、160 → 14）也吻合。
  - 表值較小的武器會抵掉一部分，但規則還沒解出來：

    | 武器（表值） | 門派 | 身法 → 攻速（武器 attack_speed 都是 1） |
    |---|---|---|
    | 匕首（185） | 天外天 | 13 → 8 |
    | 法杖（175） | 火狐 / 雪狼 | 10 → 7、11 → 7、35 → 8 |
    | 劍（180） | 移花宮 | 2 → 7、15 → 8 |
    | 扇 CLAW（180） | 曼陀 | 14 → 8 |
    | 拂塵（180） | 惡人谷 | 4 → 7 |
    | 拳刃（150） | 惡人谷 | 4 → 3 |

- **建議**：表值 185 的武器照公式算；其他武器顯示「估計」，或只顯示空手值加武器攻速。

## 5. 裝備加成

DB 欄位都在 `items`：`hp mp str pow vit dex agi wis atk matk extra_def magic_def hit dodge critical_hit uncanny_dodge attack_speed damage_min damage_max run_speed weight`。

裝備上的 `hp_flag` / `mp_flag` 都是 1（加到上限的固定值），六圍的 flag 全是 0，所以**裝備沒有百分比加成**。

**強化 `+N`**（tthol-memory `services/equip_stats.py` 的做法，用 +5 的 160 帽實測過）：

- 用 `items.strong_equipment` 找到 `strong_equipment.list`（JSON：`data[] = {level, common, bonus?}`），裡面的 id 對應 `strong_formula`。
- **`+x` 部分**：只取**目前等級**那一列 `common` 的 `bonus_type` / `bonus_value`，不是 1..N 的累加。
- **`(+x)` 部分**：等級 ≤ N 的每個 `bonus` 列加總（例如 +5、+7 解鎖的額外加成）。
- `bonus_type` 對應 `items` 欄位：`ITEM_BONUS_HP` → hp、`_MP` → mp、`_STR` → str、`_POW` → pow、`_VIT` → vit、`_DEX` → dex、`_AGI` → agi、`_WIS` → wis、`_ATK` → atk、`_MATK` → matk、`_DEF` → extra_def、`_MDEF` → magic_def、`_HIT` → hit、`_DODGE` → dodge、`_CRITICAL` → critical_hit、`_UNCANNYDODGE` → uncanny_dodge。
- genbu 已有 `src/lib/queries/compound.ts` 的 `BONUS_TO_ATTR_KEY`，可以共用。
- 只實測過 +5；更高等級是照同一規則推的，例如 Lv198 麒麟的 +16 雙劍也吻合。

**鑲嵌（真元 / 魂石）**：`compounds` 中 type 為 `ITEM_COMPOUND_EQUIPMENT` / `ITEM_COMPOUND_ORNAMENT` 的配方。效果是隨機區間，要讓使用者選數值。

**隨機屬性**：`item_rand` 只有機率表，同一件裝備每件數值不同，要讓使用者輸入。

## 6. 被動技能

### 6a. `magic_stats`（結構化，直接加）

`magic_stats(magic_id, level, stat, value, flag)`，stat ∈ `HPMAX MPMAX Atk MAtk ExtraDef MagicDef Hit Dodge Critical Encumbrance FireAttack …`。

- **每一級都疊加**：學到 Lv N = Lv1..N 的 value 加總。例如京門 Lv2 = 1200 + 1200、提托 Lv4 = 4 × 800。只算當前等級的話，天外天 Lv200 會差上千點體力。
- `flag = 'AFFECT_RATIO'` 的列是百分比，實測沒有用到，先排除。
- **收藏**（`COLLECTBOOKBONUS.INI`）的獎勵就是技能 1151～1159（體力 / 真氣 / 物攻 / 內勁 / 防禦 / 護勁 / 命中 / 閃躲 …）。UI 可以做成「收藏等級」選單，換算成這些技能的等級。
- **經脈**點也在 `magic_stats` 裡，例如 855..1125，見 `meridian.ts`。

```sql
SELECT stat, SUM(value) FROM magic_stats
WHERE magic_id = ? AND level <= ? AND (flag IS NULL OR flag != 'AFFECT_RATIO')
GROUP BY stat;
```

## 9. 屬性點（升級點數 + 轉生點數 − 加點成本）

來源：玩家自製的「角色配點模擬器」xls（2015，花無缺 / 青樓家族 V1.0），用 Excel 抽出公式後再跟實測角色核對。

**屬性點數不是「1 點加 1」：單項屬性越高，加 1 點要花越多屬性點。** 從 v−1 加到 v 的成本：

| 目標值 v | 2–10 | 11–25 | 26–40 | 41–55 | 56–70 | 71–85 | 86–100 | 101–115 | 116–128 |
|---|---|---|---|---|---|---|---|---|---|
| 每點成本 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |

- 每項屬性從 1 開始，創角的 6 點已經包含在升級點數裡。
- **規律**：除了 2–10 這段是 9 個值，之後每段都是 15 個值，每升一段成本 +1。xls 把最後一段截在 128，照規律應該是 116–130。往後推就是 131–145 為 10、146–160 為 11、161–175 為 12 …，寫成公式是 `cost(v) = v ≤ 10 ? 1 : 2 + ⌊(v − 11) / 15⌋`。131–145 = 10 已由移花宮 Lv192（外功 142）間接證實；**146 以後仍是推測**。
- 2015 年的 xls 把「不含裝備」的單項上限設成 128；**現在沒有上限**（玩家確認，2026-10），所以成本表要一直延伸下去（見下）。

|---|---|
| 1 | 6 |
| 2–25 | 2L + 4（每級 2） |

**剩餘點數 = 升級累積點數 + Σ 轉生點數 − Σ 各屬性成本。**

**實測核對**：麒麟 Lv198 扣掉裝備後六圍是 外功 99 / 內力 1 / 根骨 32 / 身法 1 / 技巧 85 / 玄學 95。

- 加點成本是 407 + 0 + 60 + 0 + 309 + 379 = **1155**。
- 升級點數照每級 7 一路延伸到 Lv198 是 7·198 − 371 = 1015；再加上 4 次 Lv140 轉生的 4 × 35 = 140，剛好 **1155**。
- 這也說明 Lv175 以後仍是每級 7 點。前提是那隻真的是四轉、每次都在 Lv140 轉，**請確認**。

上一節說的「313 點遠少於 854」是誤會，因為當時把屬性值直接當成點數加總了。

**第二隻核對（2026-10-02，多開時用 PID 區分）**：記憶體裡有「不含裝備六圍」（HP −264..−244，順序外功 / 內力 / 根骨 / 身法 / 技巧 / 玄學）和**剩餘點數**（HP −32）。

| 角色 | 不含裝六圍 | 加點成本 | 剩餘 | 升級點數 | 轉生點數 = 成本 + 剩餘 − 升級 |
|---|---|---|---|---|---|
| 天外天 Lv31 | 20 / 1 / 1 / 1 / 12 / 20 | 71 | 1 | 72 | **0**（沒轉生） |
| 移花宮 Lv192 | 142 / 1 / 36 / 1 / 74 / 1 | 1104 | 9 | 973 | **140** = 4 × 35 |
| 麒麟 Lv198 | 99 / 1 / 32 / 1 / 85 / 95 | 1155 | （當時沒讀，假設 0） | 1015 | **140** |

- 移花宮外功 142 用到「131–142 每點 10」的推算才剛好是 140；照 130 以後仍是 9 算只有 128，不是任何四轉組合的整數和。所以 **131–145 成本 10 已間接證實**。
- 轉生獎勵最高是 35（Lv140），四轉加總 140 只有一種組合：**四轉、每次都在 Lv140 轉**。轉生只能在 Lv100–140 之間（140 是轉生前的等級上限），四轉都轉完才能練到 140 以上（玩家確認，2026-10），所以不存在「Lv140 以上轉生」。
- 反推轉生只能得到四次的**總和**，不是每次的等級；總和小於 140 時會有多種組合。

## 附：傷害公式（選做）

用封包逐下擷取實測：`傷害 ≈ m·(物攻 + 武器傷害)·K/(K + 防禦) − 防禦/2`。

- m = 1 普攻、2 爆擊、技能用其 p1/100。
- K 跟怪物等級有關（Lv67～80 約 810～875，Lv22 約 626），規律還沒擬合。
- 詳見 tthol_data `scripts/damage_capture_investigation.md`。
